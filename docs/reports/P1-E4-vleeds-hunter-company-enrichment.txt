1. SUMMARY
--------------------------------------------------------------------------------
A selected business can now become a durable Vleeds company with
provider-licensed data:
  - Discover: a result saved for enrichment gets "Find company data". The
    open search's transient name runs the free domain lookup. The user
    picks or types a domain and presses "Enrich company · estimated 0.2
    credit". Hunter company data is normalized and matched (New / Existing
    company / Possible duplicate). The user chooses Create / Merge / Skip,
    and the write goes through the existing ingest_lead pipeline with Hunter
    evidence. The Place ID is linked to the committed company, so later
    searches show "Existing company".
  - It also works without Google:
      · Discover → Company data → "Enrich a company" (name or domain)
      · references saved in earlier searches (the user types a name/domain)
      · Leads → company drawer → "Enrich company"
  - The generic CompanyEnrichmentProvider contract and server-only registry
    keep every Hunter request/response shape inside one adapter folder.
  - Credits:
      · every Hunter request is accounted with an ESTIMATED credit figure
      · a compact monthly usage indicator; no hard-coded quota
      · no automatic or bulk enrichment
  - Not done (by design): contacts/decision-makers, Hunter Domain Search /
    Email Finder / Email or Combined Enrichment / Discover, Apollo, scoring,
    outreach.
Quality gate: npm.cmd run verify EXIT 0 (361/361 tests). Browser reviews:
P1-E4 configured 62/62 + not configured 8/8; regressions P1-E3 57/57 + 8/8,
P1-E2 81/81, P1-E1 40/40, S2 66/66, S1A 50/50.

4. MIGRATION / SCHEMA (20261012000000_company_enrichment_hunter.sql)
--------------------------------------------------------------------------------
  companies           + industry (≤200), description (≤2000); member
                      insert/update grants
  company_enrichment_runs
                      input_kind, discovery_candidate_id, target_company_id,
                      manual_company_name, requested/resolved_domain, status
                      (draft … failed), error_code, match_state/reason,
                      matched_company_id, decision, committed_company_id,
                      commit_result, commit_notes, timestamps
  company_enrichment_results
                      one per run: normalized durable fields, tags (≤20),
                      match
  provider_usage_events
                      + enrichment_run_id (composite FK)
                      + estimated_credit_millis (0–1,000,000 or NULL)
                      + statuses quota_exhausted, restricted
Relationships: every link is a composite same-workspace FK (candidate,
target/matched/committed company, run, usage → run).
CHECKs:
  - discovery_reference ⇒ candidate AND no stored name
  - per-kind input
  - failed ⇒ code; completed ⇒ time + result; created/merged ⇒ company
  - existing_company ⇒ company
  - employee range; size limits
Triggers:
  - guard_enrichment_run: final states frozen; completed only from review
    or processing
  - guard_enrichment_result: only while enriching, same provider
  - updated_at; immutable keys
  - guard_discovery_candidate (replaced): on a finished search only the
    needs_enrichment → selected/existing_company link is allowed
  - refresh_discovery_counts (replaced): updates the run only when the
    counts change
Indexes:
  runs     (workspace_id, created_at desc) · (workspace_id, status) ·
           (discovery_candidate_id) WHERE NOT NULL
  results  UNIQUE (enrichment_run_id) · (workspace_id, primary_domain) ·
           (workspace_id, external_record_id) WHERE NOT NULL
  usage    (enrichment_run_id) WHERE NOT NULL
ingest_lead was replaced (drop + create, same leading arguments) to add
p_enrichment_run_id and p_notes (§17).
RLS: members select/insert/update runs, select/insert results. Nothing for
anon, no deletes, column-level grants.

6. HUNTER ADAPTER
--------------------------------------------------------------------------------
  - GET only, base https://api.hunter.io/v2.
  - Key in the X-API-KEY header, never in the URL (unit-tested).
  - Timeout 10 s via AbortController.
  - Retry: one bounded retry, only for network errors, timeouts and 5xx.
    Never retried: 400/422, 401, 403 (rate limit), 429 (quota), 404, 451
    (unit-tested).
  - Error bodies are not read; status → category → fixed message.
  - Only Domain Finder and Company Enrichment are called.


--------------------------------------------------------------------------------
7. HUNTER CONFIGURATION
--------------------------------------------------------------------------------
  - HUNTER_API_KEY: server environment only; read at request time; never
    NEXT_PUBLIC_ (that name is ignored, unit-tested); absent from the
    browser bundle (bundle scan).
  - HUNTER_API_ENDPOINT: dev/review only, loopback hosts only, ignored when
    VERCEL_ENV=production (shared helper, unit-tested).
  - Without a key: Discover/Leads load; "Company enrichment is not configured
    yet."; no enrichment actions (browser-verified).
  - Setup steps: docs/providers/hunter.md §1.


--------------------------------------------------------------------------------
8. DOMAIN FINDER
--------------------------------------------------------------------------------
  - Request: company (whitespace collapsed, ≥ 3 characters; shorter names
    are refused before any request), limit ≤ 5. perfect_match is not sent.
  - Mapping: domains normalized with the lead-core helper, duplicates and
    invalid hosts dropped. companyName is kept; confidenceLabel "Exact name
    match" when the names agree; emailCount is a size hint. Logo ignored.
  - 404 or empty → "no suggestions" (the user types a domain).
  - Nothing is auto-chosen without review: the first suggestion is
    preselected, but the user always confirms through the credit-labelled
    button.
  - Beta isolation: schema + mapper only. UI and DB never see the raw shape;
    suggestions are not stored.


--------------------------------------------------------------------------------
9. DIRECT-DOMAIN FLOW
--------------------------------------------------------------------------------
"Look up by: Domain" (or a known company domain) skips Domain Finder. The
input is normalized by normalizeDomain (e.g. "https://www.X.example.test/about"
→ "x.example.test"), and the run (input_kind domain / existing_company)
goes straight to Company Enrichment on the explicit click.


--------------------------------------------------------------------------------
10. COMPANY ENRICHMENT
--------------------------------------------------------------------------------
  - GET /companies/find?domain=…; on success the durable result is recorded
    and the run moves to review.
  - 404 → "Hunter couldn't find company data for this domain." The run is
    failed with error_code not_found; the user can enter another domain. It
    is not an application failure, and no credit is estimated.
  - An unreadable success → malformed; credit estimate unknown (NULL).

11. DURABLE FIELD MAPPING (details: docs/providers/hunter.md §5)
--------------------------------------------------------------------------------
  name (else legalName, else the domain)  → canonical name
  domain                                  → primary domain
  https://<domain>                        → website URL (derived)
  phone, else site.phoneNumbers[0]        → primary phone (company line)
  geo                                     → {countryCode, region, city,
                                             postalCode, addressLine1}; no
                                             country assumed; no coordinates
  metrics.employees                       → exact count = min/max; "11-50"
                                             → range; "N+" → min; else nothing
  category.industry (one field)           → industry
  description                             → description (≤ 2000)
  tags                                    → evidence only (≤ 10)
  id                                      → lead_sources identity only
Ignored: emails, social handles/followers, logo, funding, traffic, revenue,
market cap, technology, other taxonomy codes, coordinates, parents, and so on
(unit test proves they are dropped).

--------------------------------------------------------------------------------
14. ENRICHMENT RUNS / RESULTS
--------------------------------------------------------------------------------
States:
  draft → resolving_domain → domain_review   (name lookups)
  draft / domain_review / failed → enriching → review | failed
  review → processing → completed            (create/merge, in ingest_lead)
  review → completed                         (skip)
  any open state → cancelled                 (closing the sheet)
Each transition is a filtered update ("only from …"), so double clicks can't
race. One result per run, insert-only, recorded only while enriching.
Matching outcome, decision, notes and committed company are kept on the run.


--------------------------------------------------------------------------------
15. DEDUPLICATION
--------------------------------------------------------------------------------
The lead-core hierarchy (dedupe.matchCompany), applied in order:
  1 provider identity: Hunter id OR the reference's Place ID already linked
    to an active company (lead_sources)
  2 domain
  3 international phone (review)
  4 name + same place (review)
  5 new
Results: provider identity/domain → Existing company (Merge/Skip; Create
disabled with the reason); weak → Possible duplicate (no suggestion);
started from an existing company → that company. Workspace-local (DB- and
browser-tested). No silent merge of weak matches.


--------------------------------------------------------------------------------
16. MERGE BEHAVIOUR
--------------------------------------------------------------------------------
The P1-E2 planner is reused, extended only with industry/description:
  - blank changes nothing; equal values need no change
  - empty fields are filled
  - conflicting populated values keep the Vleeds value and are reported
    (sheet + run.commit_notes)
  - the name is never changed; location/employees only fill missing values
  - qualification is untouched (enrichment never sets it)
  - a domain owned by another active company is never moved (note)
The review preview is derived from the same planner, so it cannot disagree
with the write (unit-tested).


--------------------------------------------------------------------------------
17. COMMIT THROUGH INGEST_LEAD
--------------------------------------------------------------------------------
planRowCommit (the CSV row planner) → public.ingest_lead(…,
p_enrichment_run_id, p_notes), as one transaction:
  - lock run, require processing, write company + evidence
  - link the Place ID; update the reference
  - complete the run
Idempotent: a second call returns the recorded result (DB-tested). Manual
and CSV calls are unchanged (DB test + P1-E2 regression 81/81).


--------------------------------------------------------------------------------
18. HUNTER SOURCE EVIDENCE
--------------------------------------------------------------------------------
lead_sources with source_kind api, provider_key hunter and
external_record_id = Hunter id, one row per non-empty value:
  company.name, .website, .domain, .phone, .location, .employee_range,
  .industry, .description (fitted to 2 KB), .tags
No empty values, no payloads. A repeated identity row is kept once
(on conflict do nothing; DB-tested). The drawer shows "Source: API
(hunter)" (browser-verified).


--------------------------------------------------------------------------------
19. GOOGLE PLACE ID IDENTITY LINK
--------------------------------------------------------------------------------
  - After create/merge, inside ingest_lead: lead_sources (google_places,
    Place ID, company.provider_reference, observed_value NULL) is attached
    to the COMMITTED company.
  - The reference becomes selected/existing_company → that company. This
    is allowed even on a completed search; other candidates stay frozen.
  - A concurrent second run can't re-link the reference.
  - A later search shows "Existing company" with the right company link
    (browser-verified).
